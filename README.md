# turbo-disco

このリポジトリには独立した3つのツールがあります。

- **[結婚式ムービー作成ツール](#結婚式ムービー作成ツール)**（`docs/wedding/`）
- **[競艇予想ツール](#競艇予想ツール)**（`docs/` / `server.js` + `public/` + `src/`）
- **[補助金・助成金マッチングツール](#補助金助成金マッチングツール)**（`docs/subsidy/`）
- **[Threads自動投稿ツール](#threads自動投稿ツール)**（`scripts/post-thread.js`）

## Threads自動投稿ツール

Meta社のSNS「Threads」に、指定したテキストを自動投稿するスクリプトです（`scripts/post-thread.js`）。
Threads APIの長期アクセストークンとユーザーIDを環境変数に設定して使います。

```bash
export THREADS_USER_ID=xxxxxxxxxx
export THREADS_ACCESS_TOKEN=xxxxxxxxxx

npm run post:thread -- "投稿したいテキスト"
```

- 内部的には Threads API のコンテナ作成（`POST /{user-id}/threads`）→公開（`POST /{user-id}/threads_publish`）
  の2ステップを自動で実行します。
- 投稿は500文字までです（Threads APIの制限）。
- アクセストークンは第三者に見られない環境変数・シークレットストアで管理し、リポジトリやチャットに
  直接書き込まないでください。
- 定期実行したい場合は、このスクリプトを cron や GitHub Actions の `schedule` トリガーなどから
  呼び出す形で自動化できます。
- GitHubリポジトリの Actions タブから `Post to Threads` ワークフローを手動実行（Run workflow）すると、
  パソコンがなくてもスマホのブラウザだけからテキストを指定して投稿できます。

### 子育て・補助金情報の毎日自動投稿

`scripts/thread-topics.json` に用意した子育て・補助金関連の投稿文を、
`.github/workflows/daily-thread.yml` が毎日 **8:00・13:00・20:00(JST)** の3回、順番に自動投稿します。
投稿文を追加・編集したい場合は `thread-topics.json` を直接編集してください（500文字以内）。

### コメントへの自動返信

`.github/workflows/reply-to-comments.yml` が20分おきに、自分の投稿についた新しいコメントを確認し、
Claude(Anthropic API)が内容を読んで自動で返信します（`scripts/reply-to-comments.js`）。
具体的な金額・法律要件などを断定的に答えないよう、システムプロンプトでガードレールを設けています。
返信済みのコメントIDは `replied-comments.json` に記録し、二重返信を防ぎます。
利用には `ANTHROPIC_API_KEY` と、Threads側の `threads_manage_replies` / `threads_read_replies` 権限が必要です。

### noteの記事下書きの週次自動生成

noteには公式の投稿APIが無いため自動投稿はしていませんが、記事の下書きだけは自動化できます。
`scripts/note-topics.json` に用意した記事ネタ（タイトル・無料部分・有料部分の構成案）を、
`.github/workflows/weekly-note-draft.yml` が毎週月曜 朝9:00(JST) に1つずつ `note-drafts/` フォルダへ
Markdownファイルとして書き出します。内容を確認し、そのままnoteにコピペして仕上げてください。
ネタを追加したい場合は `note-topics.json` を編集してください。

## 結婚式ムービー作成ツール

写真・動画を追加するだけで、Ken Burns風の動き・タイトルカード付きのオープニング/エンドロールムービーを
作成できるツールです。サーバー不要の静的ページで、Canvas + MediaRecorder API を使い
ブラウザ内だけで動画を生成します（写真・動画・音楽は外部に送信されません）。

- 写真だけでなく動画クリップも追加できます（1本200MBまで、ムービー内で使う長さは最大15秒まで
  調整可）。動画自体の音声は収録されず、BGMのみが収録されます。
- テンプレートを3種類用意しています。
  - **スタンダード**: Ken Burns風の動きで写真をやさしく見せるハイライトムービー。
  - **オープニング演出**: 黒背景×ネオンカラーで、カウントダウン →
    新郎パート → 新婦パート → 2人の思い出パート → クライマックス（お二人の名前発表）と
    テンポよく畳みかける、披露宴の入場・オープニング向けムービー。ノイズ・グリッチ・
    フラッシュ演出付きで、パートごとに写真をまとめて追加できます。
  - **エンドロール**: お二人の名前のタイトルカードに続けて、来賓の方々へのメッセージが
    本のページをめくるように1ページずつ表示されるムービー。紙のような質感の背景に、
    ページ送りは左端（綴じ目）を軸にページがめくれていく演出になっています。
    「＋ メッセージを追加」でお名前・メッセージ（改行可）を人数分入力でき、各メッセージに
    「グループ」（例: 新郎友人／新婦友人／ご親族）を入力すると、同じグループ名の行が
    （並び順に関係なく）まとめられます。1ページには最大4人まで入り、5人目以降は
    自動で「（つづき）」ページに分かれます。お名前とメッセージは、1人ずつ順番に
    1文字ずつタイピングされるように表示されます。写真を追加すると、グループごとの
    ページで、その写真がページ全体の背景として表示されます（写真全体が見切れない
    よう縦横比を保って表示し、余る部分は同じ写真をぼかして埋めます）。各写真の
    「背景にするグループ」欄に来賓メッセージと同じグループ名を入れておくと、
    そのグループのページ（つづきページも含む）にその写真が使われます。同じ
    グループ名の写真を複数枚追加すると、そのグループのページ数に応じて均等に
    振り分けられ、1ページに複数枚割り当たった場合はそのページの中で順番に
    切り替わるスライドショーになります（ページが1つしかないグループでも、
    その1ページの中で複数枚が順番に使われます）。各写真の「表示秒数」欄で
    スライドショー内での表示時間を個別に調整でき、空欄なら「ページを開いておく
    時間」の設定に応じた既定の長さになります。空欄の写真は専用の写真が
    無いグループに順番に自動で割り当てられます。紙の色味と、ページを開いておく
    時間（遅い／標準／速い、タイピングの速さにも連動）を設定できます。
- まず写真だけで無音のムービーを作成し、プレビュー・ダウンロードできます。
- 写真の切り替え効果は クロスフェード / スライド / ズーム / ワイプ / フラッシュ / 円形ワイプ /
  回転ズーム / ぼかし / ランダム（写真ごとに変える）から選べます（CapCut風の演出を追加）。
- 各写真にひとことキャプションを入れると、その写真が表示されている間だけ文字が重なって表示されます。
  キャプションのデザイン（シンプル／エレガント／ポップ）、文字サイズ、出し方（フェード／スライド＋フェード／
  キラキラ出現／タイプライター／バウンド／ズーム出現／常に表示）を設定欄から選べます。「キラキラ出現」は
  文字の左右から星のパーティクルが飛んできて浮かび上がる演出、「タイプライター」は1文字ずつ打ち込まれる
  演出、「バウンド」は弾むように登場する演出、「ズーム出現」は拡大しながら現れる演出です。
- **写真1枚ごとに表示時間・文字サイズ・エフェクト・表示サイズを個別調整できます。** 各写真のサムネイル
  下にある「表示秒数」欄で表示時間を、「詳細設定」を開くと文字サイズ・文字のエフェクト・写真の表示サイズ
  （％）をその写真だけ個別に上書きできます（いずれも空欄／「共通」の場合は共通設定に従います）。
  動画クリップに写真を当てこんでタイミングを合わせたい場合や、写真ごとに文字の見せ方を変えたい場合に
  使えます。写真の表示サイズを100%未満にすると、テーマカラーの余白付きで写真を小さく縁取り表示できます。
- **BGMは動画ができた後から追加できます。** 複数の音声ファイルを選ぶと、選んだ順に
  クロスフェードしながら再生し、動画の長さに足りない分は自動で繰り返します（末尾はフェードアウト）。
  オープニング演出のクライマックスでは、名前発表の直前にBGMの音量を一瞬落として「静寂の一瞬」を演出します。
- **BGMのビートに合わせた自動カットにも対応しています。** BGM追加時に「ビートに合わせて自動でカット」を
  有効にすると、先頭の曲のテンポをブラウザ内で解析し、写真・動画の表示時間をそのテンポ（1/2/4拍ごと）に
  自動で合わせて書き出します。テンポ検出は簡易的なもの（低域のエネルギーからオンセットを検出する方式）の
  ため完璧ではありませんが、アップテンポな曲であれば体感的に「ビートに合わせてカットされている」ムービーに
  近づきます。
- **完成した動画はLINEなどに直接共有できます。** 対応するブラウザ（主にAndroid/iOSのモバイルブラウザ）
  では、プレビュー動画の下に「📤 LINEなどで共有」ボタンが表示されます。押すとOS標準の共有シートが開き、
  インストール済みのLINEなどのアプリに動画ファイルをそのまま渡せます（サーバーへのアップロードは行いません）。
  対応していない環境ではボタンの代わりに案内メッセージが表示されます。「ダウンロード」または
  「🎬 新しいタブで開く」から動画を保存し、LINEアプリから送信してください。
  **「新しいタブで開く」で表示された動画は、ブラウザ自体の共有ボタン（画面のツールバーの共有アイコン）
  では正しく送れません**（動画データではなく、そのタブ限りのリンクを共有してしまうため、開くと
  404になります）。iPhoneの場合は動画を長押しして「ビデオを保存」からカメラロールに保存し、
  そこからLINEで送ってください。
  対応していれば常にMP4(H.264)形式で書き出します。iOS(Safari含む)はブラウザ上ではWebMの
  再生に対応している場合がありますが、「写真に保存」やLINEなどへの共有に使われるOS側の
  仕組みはWebMを扱えず、保存・共有が失敗する原因になるため、MP4を優先しています。
- スマホでBGMの音楽ファイルを選ぶ画面がうまく開かない・選べない場合は、LINEなどアプリ内のブラウザで
  リンクを開いていないか確認してください（アプリ内ブラウザはファイル選択が正しく動作しないことが
  あります）。Safari／Chromeで直接開くと解消することが多いです。
- **選んだ写真・動画・入力した文章を一時保存できます。** 冒頭の「📝 下書きの保存・復元」から
  「💾 今の内容を一時保存する」を押すと、その時点の写真・動画・キャプション・お名前などの入力内容・
  BGM・各種設定をこの端末のブラウザ内（IndexedDB）に保存します。ページを再読み込みして開き直すと
  「📂 下書きを復元する」ボタンが表示され、保存した内容をまとめて復元できます（生成済みの動画ファイル
  自体は保存されません。写真・動画・入力内容の下書きのみです）。外部には送信されません。
- GitHub Pages で `docs/` を公開している場合は `https://<ユーザー名>.github.io/<リポジトリ名>/wedding/`
  でそのまま使えます。ローカルでは `docs/wedding/index.html` を簡易HTTPサーバー経由で開いてください
  （`npx serve docs` など）。
- 対応ブラウザは Chrome / Edge の最新版を推奨します（MediaRecorder の WebM 出力を使用）。

## 競艇予想ツール

出走表・直前情報・オッズをリアルタイムに近い形（約3分間隔）で取得し、独自のスコアリングで
勝率・推奨買い目を算出するボートレース予想ツールです。

このリポジトリには同じ予想ロジックを使った2つの実装があります。

- **`docs/`**: サーバー不要の静的Webアプリ（PWA）。GitHub Pages でそのまま公開でき、
  スマホでホーム画面に追加すればアプリのように起動できます。**まずはこちらの利用を推奨します。**
- **`server.js` + `public/` + `src/`**: Node.js/Express 版。自分のPCやサーバーで動かす場合に。

## 特徴

- データソースは [Turnmark Boatrace Open API](https://github.com/turnmark/api)（非公式・約3分間隔で更新）。
  出走表・直前情報（進入コース/展示タイム/ST/天候）・オッズ・結果がひとつのJSONに統合されています。
- レース詳細画面は30秒ごとに自動更新し、直前情報やオッズの反映をできるだけ早く画面に反映します。
- 全国24場・全レース対応。開催場 → レース一覧 → レース詳細の順に絞り込んで表示します。
- 直前情報公開前は統計値（全国/当地勝率・モーター/ボート成績・平均ST）のみでスコアリングし、
  直前情報が公開されると進入コース・展示タイム・スタート展示を反映して再計算します。
- 単勝オッズが取得できるレースでは 期待値(勝率×オッズ) を算出し、1.00 を超える「妙味あり」の
  艇を強調表示します。3連単は上位3艇のボックス買い目を Plackett-Luce モデルで確率推定します。
- 「穴狙い」セクションで、本命(1位予想)以外の艇のうち期待値が高い単勝候補と、1着が本命以外
  になる3連単の組み合わせ（穴目）を抽出して表示します（オッズ公開後のみ）。
- 選手表・買い目の枠番は競艇の公式カラー（1白/2黒/3赤/4青/5黄/6緑）で色分け表示します。
- レース詳細画面の「過去実績・得意コース」ボタンを押すと、直近10日分のレース結果を
  横断的に集計し、選手ごとの直近成績（着順の推移）とコース別勝率から得意コースを算出します。
  データ量が多いため、初回はボタンを押すと取得を開始する仕組みにしています。
- ネットワークに繋がらない環境でも動作確認できるよう、実データを基にしたサンプルデータ表示
  モードを搭載しています（過去実績機能はサンプルモードでは利用できません）。

## 公開する（GitHub Pages・推奨）

`docs/` フォルダはサーバー不要の静的PWAで、ブラウザから直接データソースを取得します。
GitHub Pages を有効にするだけで、誰でもURLからアプリとして使えるようになります。

1. GitHubでこのリポジトリの **Settings → Pages** を開く
2. **Build and deployment → Source** を「Deploy from a branch」に設定
3. **Branch** で公開したいブランチ（例: `main`）と **フォルダを `/docs`** に設定して **Save**
4. 数分後、`https://<ユーザー名>.github.io/<リポジトリ名>/` でアクセスできるようになります

公開後、スマホのブラウザでそのURLを開き「ホーム画面に追加」すると、アイコンから
アプリのように起動できます（PWA）。

## ローカルで動かす（Node.js版）

自分のPC・サーバーで動かしたい場合は Node.js 版を使えます。

```bash
npm install
npm start
```

`http://localhost:3000` を開いてください。デフォルトのポートは `PORT` 環境変数で変更できます。

## 使い方

1. 画面右上の日付で表示したい開催日を選択します（デフォルトは当日・日本時間）。
2. 開催場を選ぶとレース一覧（1R〜12R）が表示されます。カードの状態タグで
   「出走表のみ / 直前情報あり / オッズ確定 / 確定」の進行状況がわかります。
3. レースを選ぶと選手ごとの予想勝率・印(◎○▲△×)・推奨3連単ボックスが表示されます。
   レース確定後は結果と払戻金も表示されます。

「サンプルデータ表示」ボタンを押すと、実際のAPIレスポンスを保存した過去レース
（2026-04-01・桐生/常滑/大村）を使ってオフラインで動作を確認できます。

## 予想アルゴリズムについて

`src/predictor.js`（Node版）/ `docs/predictor.js`（静的版・内容は同一）にスコアリングロジックが
あります。主な考慮要素と重み付けは以下の通りです。

| 要素 | 重み(目安) | 備考 |
|---|---|---|
| 進入コース | 最大 | コース別全国平均1着率(1コース55%〜6コース3%)を反映。直前情報公開後のみ使用 |
| 全国勝率・当地勝率 | 中 | 選手の基礎成績 |
| モーター/ボート2連率 | 中 | 機力 |
| スタートタイミング(展示ST) | 中 | 直前情報公開後は展示のSTを、公開前は平均STを使用 |
| 展示タイム | 中 | 直前情報公開後のみ |
| チルト調整 | 小 | 直前情報公開後のみ |

強風(6m以上)・高波(5cm以上)の場合はコースの優位性をやや割り引き、荒れ注意を表示します。
各艇のスコアを softmax で正規化して勝率(%)に変換し、Plackett-Luce モデルで3連単の確率を
推定しています。重みは `WEIGHTS` 定数として `src/predictor.js` にまとめてあるので、
チューニングしたい場合はそこを調整してください。

**この予想は参考情報であり、的中や利益を保証するものではありません。舟券の購入は
自己責任で行ってください。**

## 構成

```
docs/                   静的PWA版（GitHub Pages公開用、サーバー不要）
  index.html/app.js/client.js  UI・データ取得（ブラウザから直接APIへfetch）
  predictor.js/stadiums.js     予想ロジック（src/ と同一内容）
  history.js/dayCache.js       過去実績集計（IndexedDBに日別データを永続キャッシュ）
  manifest.webmanifest/sw.js   PWA設定・サービスワーカー
  fixtures/                    サンプルデータ表示モード用の実データ（2026-04-01）

server.js              Express サーバー・APIエンドポイント（Node版）
src/turnmarkClient.js  外部APIの取得・キャッシュ（TTL 60秒）・ミラーフォールバック
src/predictor.js        予想スコアリングロジック
src/stadiums.js         競艇場番号 → 場名マッピング
src/dateUtil.js         日本時間の日付ユーティリティ
src/history.js          過去実績集計（メモリ内に日別データを永続キャッシュ）
public/                 Node版フロントエンド（素のHTML/CSS/JS、ビルド不要）
fixtures/               サンプルデータ表示モード用の実データ（2026-04-01, Node版用）
```

## 注意事項

- データソースは非公式のオープンAPI（turnmark/api）です。公式サイトとは一切関係なく、
  正確性・完全性は保証されません。重要な情報は公式サイトで確認してください。
- 静的PWA版はブラウザから直接 `turnmark.github.io`（および そのミラーの
  `raw.githubusercontent.com`）にアクセスします。Node版はサーバーがそこに到達できる
  ネットワーク環境が必要です。
- turnmark/apiにその日のファイルがまだ無い場合（実際にレースが開催中でも、
  データ提供元側の生成が追いついていないことがあります）は、同系統・同スキーマの
  [boatraceopenapi/api](https://github.com/boatraceopenapi/api)（オッズ非対応）に
  自動でフォールバックします。フォールバック中は画面上部のステータス表示に
  「（代替データ・オッズ非対応）」と表示され、単勝オッズ・期待値・穴狙いセクションは
  利用できません。

## 補助金・助成金マッチングツール

個人事業主〜中小企業・法人向けに、事業の情報（都道府県・従業員数・業種や実施したいこと等）を
入力すると、条件に近い補助金・助成金を検索できるツールです。サーバー不要の静的ページで、
`docs/subsidy/` にあります。GitHub Pages で `docs/` を公開している場合は
`https://<ユーザー名>.github.io/<リポジトリ名>/subsidy/` でそのまま使えます。ローカルでは
`docs/subsidy/index.html` を簡易HTTPサーバー経由で開いてください（`npx serve docs` など）。

検索対象データは、ブラウザから[jGrants](https://www.jgrants-portal.go.jp/)の公開APIを直接呼び出すのでは
なく、`.github/workflows/refresh-subsidies.yml`（GitHub Actions）が1日1回サーバー側で取得し、
`docs/subsidy/data/subsidies.json` として保存したものを読み込んでいます。jGrants APIはブラウザからの
直接アクセス（CORS）を許可していないため、この方式にしています。そのぶん、最新の公募開始・締切が
反映されるまで最大1日程度のずれが生じることがあります。

### 使い方

1. 事業形態（個人事業主／法人）・都道府県・市区町村（任意）・従業員数を入力します。
   事業形態に応じて、今年度・前年度の年商（法人）または所得（個人事業主）の入力欄も
   表示されます。
2. 「気になるテーマ」から「販路拡大」「IT導入・デジタル化」などのタグをクリックして
   複数選択できます（任意。選ばなければ全件が対象になります）。
3. 「この条件で検索する」を押すと、前日までに取得済みのjGrantsデータの中から条件に近い制度を
   検索します。結果をクリックすると、補助上限額・補助率・募集期間などの詳細と、jGrantsの
   制度詳細ページへのリンクが表示されます。ページを開いた時点でも、募集中の制度が自動で
   一覧表示されます。
4. 今年度・前年度の年商（所得）を両方入力し、前年度より減少している場合は、「売上減少に
   関連する制度（参考）」欄が表示されます。減少率を計算して表示するとともに、jGrantsデータの
   中から関連しそうな制度をあわせて検索し、加えてセーフティネット保証・セーフティネット貸付
   など、売上減少を要件とする代表的な資金繰り支援制度（信用保証協会・日本政策金融公庫が
   実施するもの）を参考として案内します。これらはjGrantsには掲載されない融資・保証制度のため、
   対象業種・減少率などの具体的な要件は載せていません。必ず最寄りの信用保証協会・日本政策金融
   公庫・商工会議所で最新の要件をご確認ください。
5. ページ下部には、商工会議所・商工会や中小企業庁などが実施する全国規模の代表的な制度名を
   参考リストとして常に表示します（金額・締切は載せていません。制度改定のたびに変わるため、
   名称で検索したうえで必ず公式サイト・最新の公募要領を確認してください）。

入力した事業の情報はこの端末のブラウザ内（localStorage）にのみ保存され、外部には送信されません。

### データ取得の仕組み（GitHub Actions）

- `scripts/fetch-subsidies.js` が、複数の検索語（「補助金」「販路拡大」「IT導入・デジタル化」など）で
  jGrants APIを検索し、重複を除いてまとめたうえで各制度の詳細（実施団体・補助率など）も取得し、
  `docs/subsidy/data/subsidies.json` に書き出します。
- `.github/workflows/refresh-subsidies.yml` がこのスクリプトを毎日6:00 JSTに実行し、変更があれば
  自動でコミット・pushします。GitHubの「Actions」タブから `Refresh Subsidy Data` を手動実行
  （Run workflow）することもできます。
- 初回実行が完了するまでは `docs/subsidy/data/subsidies.json` は空のプレースホルダーのままなので、
  検索結果は0件になります（参考リストは初回実行前でも利用できます）。

### データについて・制約

- 検索対象データは、複数の検索語でjGrants公開APIを検索してまとめたスナップショットです。
  jGrantsに登録されている制度すべて、また都道府県・市区町村・商工会議所の制度すべてを
  網羅しているわけではありません。お住まいの市区町村や地域の商工会議所・商工会が独自に行っている
  制度については、それぞれの公式サイトでの確認をおすすめします。
- jGrantsは主に経済産業省・中小企業庁系の「補助金」を対象としており、厚生労働省系の「助成金」
  （雇用調整助成金、キャリアアップ助成金など）は含まれません。
- 検索結果・参考リストは申請の可否を保証するものではありません。応募要件・締切・提出書類は
  必ず実施団体の公式サイト・最新の公募要領でご確認ください。
